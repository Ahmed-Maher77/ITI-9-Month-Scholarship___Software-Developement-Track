## Lesson 04: Peer-to-Peer (P2P) vs Client/Server — Two Core Networking Models

In this lesson, we explored two fundamental architectural models that define how devices communicate and share resources over a network: **Peer-to-Peer (P2P)** and **Client/Server**.

---

## 🤝 1. Peer-to-Peer (P2P) Model

In a P2P network, every device (node) acts as both a client and a server at the same time.  
There is no central authority — nodes communicate and share resources directly with each other.

### 🧩 Key Features
- No central server  
- All nodes are equal  
- Resources are shared directly  
- Easy and inexpensive to set up  

### ⭐ Examples
- Torrent networks (BitTorrent)  
- File-sharing systems  
- Local networks between a small number of PCs  

### 🟢 Advantages
- No single point of failure  
- Cost-effective  
- Simple to configure  

### 🔴 Disadvantages
- Hard to manage as the network grows  
- Lower security  
- Data consistency is difficult to maintain  

---

## 🖥️ 2. Client/Server Model

In a Client/Server network, communication relies on a central server that provides services and resources, while clients send requests and receive responses.

### 🧩 Key Features
- Centralized management  
- Dedicated server(s)  
- Clients depend on the server for resources  

### ⭐ Examples
- Web applications  
- Email servers  
- Database servers  

### 🟢 Advantages
- Strong security and access control  
- Easy to manage and scale  
- Centralized data → more consistent  

### 🔴 Disadvantages
- Higher cost (needs servers + maintenance)  
- Single point of failure if not redundant  

---

## 🆚 P2P vs. Client/Server: Quick Comparison

| Feature              | Peer-to-Peer (P2P)       | Client/Server               |
|---------------------|------------------------|----------------------------|
| Architecture        | Decentralized           | Centralized                |
| Central Server      | ❌ No                   | ✔️ Yes                     |
| Cost                | Low                     | Medium-High                |
| Security            | Weak                    | Strong                     |
| Scalability         | Low/Medium              | High                       |
| Examples            | Torrents                | Websites, Databases        |

---

## 📌 Summary

Both models have their own strengths — **P2P** is great for small, cost-effective networks, while **Client/Server** is ideal for scalable and secure enterprise systems.
