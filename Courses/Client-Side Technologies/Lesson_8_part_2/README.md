## Lesson 8 (Part 2): Accessibility & Best Practices ♿

---

## 📘 Introduction

Accessibility (A11y) ensures that everyone — regardless of ability — can use and enjoy your website. It's not just a technical requirement, but a key part of ethical and inclusive design.

---

## 🔗 1️⃣ ARIA (Accessible Rich Internet Applications)

When HTML alone isn't enough, ARIA attributes help make interactive elements accessible.

### 💡 Example:

```html
<button aria-label="Close menu">X</button>
```

### ✅ Common ARIA Attributes:

- **`aria-label`** — Gives an accessible name.
- **`role`** — Defines purpose (e.g., `role="navigation"`).
- **`aria-hidden="true"`** — Hides decorative elements.

---

## 💡 2️⃣ Best Practices for Accessibility

✅ Use Proper Heading Structure (`<h1>` → `<h6>`)  
✅ Provide Text Alternatives (alt for images)  
✅ Ensure Sufficient Color Contrast  
✅ Test Navigation Using Keyboard Only (`tabindex`, `accesskey`)  
✅ Define the Page Language (`<html lang="en">`)  
✅ Use Labels and Descriptive Inputs (`for`, `name`, `id`)  
✅ Specify Button Types Clearly (`type="button|submit|reset"`)  
✅ Use Landmarks & Roles (`<footer role="contentinfo">`)  
✅ Provide Captions and Transcripts for Multimedia  
✅ Add ARIA Attributes When Necessary  
✅ Ensure Focus Visibility (`outline`, `box-shadow`)  
✅ Use Descriptive Link Texts (`<a href="/courses">View available courses</a>`)  
✅ Avoid Auto-Play and Movement Without Control

---

## 🌟 Key Takeaways

- Accessibility is essential for inclusive, user-friendly websites.
- ARIA attributes enhance usability for assistive tools.
- Following accessibility standards improves UX, SEO, and credibility.
