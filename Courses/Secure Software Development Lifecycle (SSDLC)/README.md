# Secure Software Development Lifecycle (SSDLC) — ITI 9-Month Professional Training Program

As part of my journey at the Information Technology Institute (ITI), I completed an in-depth course on Secure Software Development Lifecycle (SSDLC), which fundamentally changed the way I think about building software, shifting security from an afterthought to a core design principle.

---

## What I learned in this course

### Why security matters

Understanding that software security is directly tied to business reputation, customer trust, and financial stability, not just technical correctness.

### SSDLC vs SDLC

Learning how to embed security into every phase of the development lifecycle:

- Requirements -> Risk Assessment
- Design -> Threat Modeling
- Development -> Secure Coding and Static Analysis
- Testing -> Security and Penetration Testing
- Deployment and Maintenance -> Secure Configuration, Monitoring, and Patch Management

This approach is far more cost-effective than fixing vulnerabilities after release.

### Core security foundations

- CIA Triad: Confidentiality, Integrity, Availability
- AAA: Authentication, Authorization, Accountability
- Authentication factors: knowledge, possession, and biometrics

### Risk and threat awareness

- Identifying assets, threats, vulnerabilities, and risks
- Performing risk assessment and classification
- Using CVSS to assess vulnerability severity objectively

### Secure requirements and design

- Translating business and regulatory needs into security requirements
- Applying secure design principles (least privilege, defense in depth, fail secure)
- Performing threat modeling to anticipate real attack scenarios early

### Secure implementation

- Writing secure code aligned with OWASP Top 10
- Understanding common attacks (SQL Injection, XSS, OS Command Injection, File Inclusion)
- Leveraging vulnerability databases such as CVE, CWE, NVD, and US-CERT

### Security testing and assessment

- Web Application Security Testing (WAST)
- Black-box and white-box testing
- Vulnerability Assessment and Penetration Testing (VAPT)
- Proper security defect reporting, prioritization, and tracking

### Incident response and maintenance

- Incident detection, containment, recovery, and post-incident analysis
- Security patch management
- Secure software decommissioning and data/media sanitization

---

## Key mindset

Secure software is not written by chance, it is designed, implemented, tested, and maintained with intent.
