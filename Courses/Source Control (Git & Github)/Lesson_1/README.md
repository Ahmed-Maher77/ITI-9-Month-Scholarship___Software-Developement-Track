# 🎓 Source Control (Git & GitHub) — ITI 9-Month Journey  
## Lesson 1: Introduction to Version Control & Why Git

Understanding Version Control is the first essential step in building reliable, maintainable, and collaborative software.  
Whether you're working solo or in a team, version control helps you track progress, organize changes, and avoid losing important work.

---

## 🔍 What Is Version Control?

Version Control (also known as Source Control) is a system that allows developers to:

- Track every change in their codebase  
- Restore previous versions when needed  
- Collaborate without overwriting each other’s work  
- Document what changed and why  

It acts as a **time machine** for your project — giving you safety, clarity, and full control over your code history.

---

## 🧩 Why Developers Need Version Control

Version control is a must-have skill in real software teams. It helps you:

### ✔ Work Together Without Conflicts  
Multiple developers can edit the same project safely using branches, merges, and pull requests.

### ✔ Track Changes Accurately  
Every modification is recorded, along with the author and timestamp.

### ✔ Fix Bugs Faster  
You can easily restore a stable version if something breaks.

### ✔ Build Features Independently  
Branches let you experiment without affecting the main product.

---

## 🗂 Types of Version Control Systems

There are three main version control models:

### **1. Local Version Control**  
Stores all versions on a single device.  
- No collaboration  
- No synchronization  
- Suitable only for individual developers  

### **2. Centralized Version Control (CVCS)**  
A single server stores the repository.  
- Requires constant connectivity  
- Server failure stops all work  
- Examples: SVN, Perforce  

### **3. Distributed Version Control (DVCS)**  
Each developer has a full copy of the repository and its history.  
- Work offline  
- Fast operations  
- More reliable  
- **Git** is the most widely used DVCS.

---

## 🆚 Git vs GitHub — What’s the Difference?

Many beginners confuse the two:

- **Git** → A tool installed on your machine to track code history  
- **GitHub** → A platform that hosts Git repositories online  

You can use Git without GitHub, but GitHub makes collaboration efficient and organized.

Alternative hosting services: GitLab, Bitbucket.

---

## 💡 Real-World Example

Imagine you're building a website and introduce a bug after a long coding session.  
Without version control → you manually search for the mistake.  
With Git → you simply inspect commits, compare changes, and revert instantly.

That’s the power of version control.

---

## 🔑 Key Takeaways

- Version Control protects your work and ensures smooth collaboration  
- Git is the industry-standard Distributed VCS  
- GitHub is a hosting platform, not Git itself  
- Version history helps with debugging, documentation, and teamwork  
- Using Git leads to cleaner, more maintainable projects
