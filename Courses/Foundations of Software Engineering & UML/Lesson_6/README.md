# 🎓 Software Requirements Engineering & UML — ITI 9-Month Journey

## Lesson 6: Functional & Non-Functional Requirements + Validation Essentials

In today's lesson, I explored one of the most important topics in SRE — the difference between Functional and Non-Functional Requirements, and how to ensure documented requirements are correct and usable.

---

## 🔹 Functional Requirements (FR)

These define **what the system should do** — visible features and behaviors.

### Examples:

-   "System shall allow users to reset their password."
-   "System shall send a booking confirmation email."

### Characteristics:

-   User-facing
-   Describe actions, processes, and business rules
-   Typically captured in User Stories, Use Cases, or SRS documents

---

## 🔹 Non-Functional Requirements (NFR)

These describe **how the system should perform** — quality attributes and constraints.

### Key Categories:

-   **Performance**: Response time, throughput
-   **Security**: Access control, encryption
-   **Usability**: Accessibility, UI consistency
-   **Reliability**: Uptime, fault tolerance
-   **Scalability**: Ability to handle growth
-   **Maintainability**: Ease of updates
-   **Portability**: OS/browser compatibility
-   **Compliance**: GDPR, ISO standards

### 📌 Example NFR:

> "System shall respond within 2 seconds under normal load."

**Functional = make the system useful**  
**Non-functional = make the system usable**

---

## 🔹 Requirements Validation

Validation ensures that requirements are:

-   ✔ **Correct**
-   ✔ **Complete**
-   ✔ **Consistent**
-   ✔ **Feasible**
-   ✔ **Testable**

### Common Techniques:

-   **Review/Inspection**: Peer review to catch conflicts.
-   **Prototyping**: Validate UI/UX with users.
-   **Test Cases**: Ensuring each requirement is verifiable.

### 📌 Example:

**Requirement**: "System shall allow users to upload files up to 5MB."  
**Validation test**: Upload a 6MB file → System must reject it.

---

## Key Takeaways

✅ Functional = what the system does.  
✅ NFRs = how the system behaves.  
✅ Validating requirements early saves time, effort, and reduces rework.
